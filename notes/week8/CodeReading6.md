1.Agent 和 Server 之间使用的是 TCP 协议（基于 Socket）。
它们之间传输的数据格式是 Protobuf（Protocol Buffers)格式。在项目里可以看到 `RCRSProto.java`，这是官方已经定义好并编译好的 Protobuf 消息类，Agent 和 Server 之间就是通过发送 Protobuf 序列化后的二进制字节流来通信的。

2.因为网络传输只能传输“字节流（0和1）”，不能直接传输 Java 内存里的对象。所以必须把 Java 对象变成一串二进制字节，这就是序列化。到了对面之后，再把字节还原成对象，也就是反序列化。
直接传 Java 对象（即用 Java 原生序列化）不太行，主要有两个原因：
1. **语言局限性：** Server 是用 Java 写的，但以后编写的 Agent 可能用 Python、C++。Java 原生的序列化流只有 Java 虚拟机才能解析，别的语言根本读不懂。
2. **效率太低：** Java 原生序列化保存了非常多的类结构信息，导致数据包体积非常大、解析速度慢。
而项目里用的 Protobuf，是跨语言的、二进制紧凑格式，体积小、解析快，非常适合这种需要高频、实时通信的救援模拟场景。
