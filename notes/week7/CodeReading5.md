1.按我的理解，这是一段用 Java 8 的 Stream 流来批量创建线程的代码。解释一下它的步骤：
1. `connectors.stream()`：先把当前项目里存着的“连接器列表（Connector）”转成了一个流（Stream），方便后续做批量操作。
2. `.map(connector -> new Thread(() -> {...}))`：这是核心步骤。`map` 类似于一个“映射”操作，它把列表里的每一个 `connector` 对象，都通过 Lambda 表达式映射成一个新的 `Thread` 线程对象。这个线程里面执行的代码，就是 Lambda 里定义的“去连接 Server”的逻辑。
3. `.collect(...)`：把刚才 `map` 生成的这一堆新的 `Thread` 线程对象，重新收集起来，存到一个 `List<Thread>`（线程列表）里面，方便后面去统一 `start()` 启动它们。
 
 2.因为每个 `Connector` 代表一个智能体（Agent）要去连接仿真服务器。如果按顺序串行连接，那就像排队买饭一样，第一个人（第一个 Agent）连完、登记好之后，第二个人才能继续连接。
在真实的 RoboCup 场景里，可能有几十甚至上百个 Agent 同时需要上线。如果串行去连，光等待连接建立的时间就会非常漫长，导致整个系统启动超级慢。
启动独立线程，就相当于让所有 Agent 在同一时刻各自派人去“敲门”连接服务器，多个连接动作并行处理，能极大地缩短所有 Agent 完成连接的总耗时。
